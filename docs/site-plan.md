# 个人网站产品方案

> 版本 v1.1 · 2026-10-23 · 基于 PRD v1.0 细化
> 配套视觉稿：`design/prototype.html`（可交互，含暗色模式与移动端）
> 说明：视觉稿中的人名、公司、项目和文章均为示例内容，仅用于判断版式、节奏与语气。
> 当前全站设计规范以根目录 `DESIGN.md` 为准；本文保留产品方案与历史决策。

---

## 0. 方案摘要

**一句话定位**：一个以「人」和「文字」为主体的个人站点——首页让人 30 秒认识你，Notes 让你在 10 分钟内发布一篇随笔。

**核心策略**：把维护成本压到最低，把表达密度提到最高。

- 不做作品集模板，不做后台，不做数据库。站点是「一份可被阅读的简历 + 一本持续生长的笔记」。
- 介绍性内容分为 About 与 Work 两页：前者专注个人简介，后者承载完整经历与项目，避免首页信息过载。
- 写作流程只有一条：Markdown → Git push → 自动构建上线。没有任何需要登录的中间层。
- 视觉走「近白暖纸 + 青碧强调 + 衬线标题 + 克制动效」，比纯白文档站更有温度，但不做视觉表演。

**本方案在 PRD 基础上补充的决策**：

| 议题 | 决策 |
| --- | --- |
| 暗色模式 | 支持。跟随系统，可手动切换并记忆；使用暖黑而非纯黑 |
| 字体加载 | 自托管西文子集，中文走系统宋体/黑体栈，不加载全量 CJK 字体 |
| 内容校验 | 用 Zod schema 在构建时强制 `title / date / summary`，缺字段直接构建失败 |
| 分发能力 | 首版即带 RSS、sitemap、404 页、每篇独立 OG 元信息 |
| 统计 | 首版不装；需要时用无 Cookie 的 Umami，脚本 ≤ 2KB |
| 维护机制 | 明确「写作 SOP + 周/月/季/年维护日历 + 备份归属」，不靠自觉 |

## 1. 产品目标与衡量方式

| 目标 | 衡量方式 | 首版阈值 |
| --- | --- | --- |
| 访客快速理解你 | 首屏（不看滚动）能读到身份、方向、联系方式 | 是 / 否 |
| 写作摩擦足够低 | 从新建文件到线上可访问的实际耗时 | ≤ 10 分钟 |
| 可持续更新 | 上线后 6 个月内新增笔记数 | ≥ 6 篇（约每月 1 篇） |
| 访问体验 | Lighthouse 性能 / 可访问性 | ≥ 95 / 100 |
| 页面轻量 | 首屏 JS + 字体体积 | JS < 20KB，字体 < 120KB |

> 说明：不把 PV、粉丝数作为目标。个人站点的价值在「被正确的人看到时足够可信」，而不是流量。

**非目标**（沿用 PRD）：评论、登录、Newsletter 后台、可视化 CMS、多语言、全文搜索。其中搜索列为 M3 可选，用 Pagefind 纯静态实现，不引入服务端。

## 2. 信息架构

```
/                    Home（简介、经历项目入口、最近 3 篇笔记）
/about               About（个人简介与联系方式）
/work                Work（工作经历与归属各经历的代表项目）
/notes               全部笔记（按年份分组）
/notes/[slug]        正文
/404                 未找到
/rss.xml             RSS
/sitemap-index.xml   Sitemap
```

**导航模型**：顶栏保留 `About`、`Work`、`Notes` 和主题切换，不放置站名与头像。当前页用下划短线 + 颜色区分，不用背景块，避免和毛玻璃胶囊打架。

**页面约定**：首页的经历摘要链接到 `/work`；About 只承担个人介绍。各页面顶部直接切换，不做路由过渡；Work 内的时间线锚点保留平滑滚动。

## 3. 视觉风格

### 3.1 设计原则

1. **纸，不是屏幕**：近白暖底、微弱颗粒、低对比边界。让人读长文时不觉得在「看 UI」。
2. **排版即品牌**：不用插画和渐变堆气氛，靠字号对比、留白节奏和衬线字形建立记忆点。
3. **动效只做三件事**：进场时轻轻浮起、悬停时确认可点、首屏方块阵随指针局部抬升。其余一律不动。
4. **克制的颜色**：全站只有一个强调色（青碧），只出现在链接、强调词和极少数图标上。冷色只做点缀，不大面积铺开。

### 3.2 色彩系统

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#FEFDFA` | `#14120F` | 页面底色（近白暖纸 / 暖黑） |
| `--bg-soft` | `#F7F3EB` | `#1A1714` | 分区底色、代码块外框 |
| `--surface` | `rgba(255,255,255,.85)` | `rgba(30,26,22,.62)` | 毛玻璃顶栏 |
| `--surface-solid` | `#FFFFFF` | `#1E1A16` | 卡片实体表面 |
| `--ink` | `#1B1916` | `#F3EDE3` | 标题、正文主色 |
| `--ink-2` | `#4A443C` | `#CFC5B7` | 次级正文 |
| `--muted` | `#6E6558` | `#A99E8F` | 日期、说明、页脚 |
| `--line` | `rgba(27,25,22,.10)` | `rgba(243,237,227,.12)` | 分隔线、卡片描边 |
| `--accent` | `#17A8B8` | `#17A8B8` | 基础色；用于装饰与浅底派生（浅色底 2.82:1，不直接用于文字） |
| `--accent-ink` | `#0B7481` | `#4FCBD8` | 链接、标签、强调词、行内代码，浅色 5.39:1 / 暗色 9.67:1 |
| `--accent-soft` | `rgba(23,168,184,.10)` | `rgba(23,168,184,.16)` | 标签底、悬停底、选中态 |

**用法比例**：底色 60%、文字 30%、强调色 ≤ 10%。强调色不做大面积背景，不用于装饰性色块。

**青碧的两级用法**：`--accent` 是在近白纸底上的 2.82:1，只适合做细线、装饰色块、选中底这类非文字信号；所有需要阅读的文字（链接、标签、强调词、行内代码）统一用 `--accent-ink`，浅色模式 5.39:1、暗色模式 9.67:1。不要为了「更亮」把文字改成 `--accent`。

**对比度**：正文/背景 ≥ 9:1；`--muted` 在两种模式下均 ≥ 4.5:1；链接默认带下划线，不单靠颜色传达可点击。

### 3.3 字体系统

| 角色 | 字体 | 说明 |
| --- | --- | --- |
| 标题 / 强调 | `"Instrument Serif", "Songti SC", "Source Han Serif SC", "Noto Serif SC", serif` | 西文用开源衬线；中文自动落到系统宋体，气质一致 |
| 正文 / UI | `"DM Sans", -apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` | 正文不使用衬线，保证中文小字清晰 |
| 代码 | `"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, monospace` | 仅代码块与行内代码 |

**不加载全量中文 Web Font**：一套 CJK 字体动辄 3–8MB，与「轻量」目标冲突。首版用系统字体；若后期发现 Windows 宋体在大标题上效果差，再对 H1/H2 用到的字符做子集化（约 60–120KB）。

**字号阶梯**

| 角色 | 桌面 | 移动 | 行高 | 字距 | 字重 |
| --- | --- | --- | --- | --- | --- |
| Display（首页 H1） | 76px | 41px | 1.06 | -0.02em | 400 |
| H1（文章标题） | 50px | 34px | 1.14 | -0.015em | 400 |
| H2（区块标题） | 32px | 26px | 1.25 | -0.01em | 400 |
| H3（卡片标题） | 20px | 19px | 1.4 | 0 | 500 |
| Lede（导语） | 19px | 17.5px | 1.7 | 0 | 400 |
| Body | 16.5px | 16px | 1.75 | 0.01em | 400 |
| Meta（日期） | 13.5px | 13px | 1.5 | 0.02em | 400 |
| Label（小标签） | 11.5px | 11px | 1.4 | 0.16em | 500，大写 |

**中文排版细节**：正文行宽 36–40em（约 620–680px）；段间距 1.1em 而非空行；中英混排由浏览器默认处理，不手动加空格；标点使用全角；标题避免单字成行（`text-wrap: balance`）。

### 3.4 空间、圆角与阴影

- 间距基准 4px，常用步进：8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。
- 容器宽 1160px，正文列 680px，页面左右留白 24px（移动）/ 32px（桌面）。
- 圆角：胶囊 999px；大卡片 22px；项目卡 16px；图片 14px；标签 999px。
- 阴影只分三级，暗色模式下降阴影强度、改用描边表达层级：

| 层级 | Light | 用途 |
| --- | --- | --- |
| `shadow-1` | `0 1px 2px rgba(27,25,22,.05)` | 卡片静态 |
| `shadow-2` | `0 10px 30px -18px rgba(27,25,22,.25)` | 顶栏、悬停 |
| `shadow-3` | `0 20px 44px -24px rgba(27,25,22,.35)` | 项目卡 hover |

### 3.5 关键组件

**毛玻璃顶栏**：`position: fixed`，顶部 18px；首屏为与正文对齐的无边框通栏导航，向下滚动超过 72px 后以 560ms 缓动收拢为 304px 居中小胶囊，回到 24px 以内时展开。收拢态使用 `backdrop-filter: blur(18px) saturate(1.25)` + 1px 半透明描边与柔和阴影，文字和控件尺寸不变；移动端始终保持全宽。

**卡片**：1px 描边 + 极浅底 + 22px 圆角；内部用 1px 分隔线切成 Experience / Projects 两段，段标题用 Label 样式。悬停不整体放大，只对内部项目卡做 `translateY(-2px)`。

**链接**：正文链接默认 `text-decoration: underline`，`text-underline-offset: 3px`，`text-decoration-thickness: 1px`，颜色为 `--accent-ink`；悬停时下划线加粗到 2px，不做颜色跳变。

**标签**：`--accent-soft` 底 + `--accent-ink` 字，11.5px，上下 4px 左右 10px，不做描边。

**按钮**：本站几乎不需要按钮。唯一的「查看全部笔记 →」用文字链接 + 箭头位移动效（悬停右移 3px），不用填充按钮。

### 3.6 动效

| 场景 | 参数 |
| --- | --- |
| 首屏进场 | opacity 0→1，translateY 12px→0，520ms，`cubic-bezier(.22,1,.36,1)`，同组元素 stagger 60ms |
| 区块滚动进场 | IntersectionObserver，进入视口 12% 时触发一次，不重复 |
| 首屏方块阵背景 | 静止隐藏；指针进入空白区域 160ms 淡入，150px 半径内方块上抬 9px 并染强调色，离开 380ms 回落；文本、标签与导航区域不触发，触屏与 reduced-motion 不启用 |
| 卡片悬停 | 200ms，`translateY(-2px)` + 阴影升级 |
| 链接箭头 | 180ms 位移 |
| 路由切换 | 仅 120ms 淡入；不做左右滑动或整页过渡 |

全部动效在 `prefers-reduced-motion: reduce` 时降级为无位移、无动画。

### 3.7 暗色模式

- 默认跟随系统（`prefers-color-scheme`），手动切换后写入 `localStorage` 并加 `data-theme`。
- 用暖黑 `#14120F`，不用 `#000`；卡片靠「提亮表面 + 描边」而非阴影分层。
- 图片在暗色下不做整体降亮（会失真），改为加深描边；代码块在两种模式下都保持深色，视觉上作为「墨块」。
- 切换按钮放在导航右侧，图标 16px；避免首屏闪烁——在 `<head>` 内联 3 行脚本提前设置主题。

## 4. 页面布局

### 4.1 首页（桌面 ≥ 960px）

> 2026-10-23 调整：首页 hero 已改为两栏布局（左栏头像 + 社交入口，右栏姓名 + 定位句 + 简介），话题标签另起一行排在简介末尾；姓名使用 Array 点阵字体、标签使用 Striper 描边字体；下方 ASCII 图为早期方案，保留作历史参考。

> 以下像素值以 `design/prototype.html` 为准；实现时直接复用其中的 token 与间距。

**规格**：Hero 上留白 148px（含导航高度），下 84px；卡片内边距 34px；经历行左列 128px（年份），行间距 32px；项目网格 `gap: 16px`，两列等宽；最近笔记区距卡片 76px。

**信息取舍**：首屏只放「定位 + 一句补充 + 简介 + 联系方式」，不放头像，也不在导航中放站名。避免把首页做成模板化 Hero，让文字本身承担识别。

### 4.2 首页（移动 < 761px）

- 导航保留完整宽度与 About / Work / Notes / 主题切换，不收缩为小胶囊。
- H1 降到 40px，行高 1.1；简介 16px。
- 首页只展示经历与项目的摘要入口，完整内容在 Work 页阅读。
- 联系方式横向排列，必要时换行。

### About 页纸版草原

- 顶部使用 100vw 全幅纸版草原，与 Work 共享桌面 360px、平板 320px、移动端 250px 的统一场景高度，底部渐隐进入页面底色，页面切换时不产生尺寸跳变。
- 远景丘陵、中景野马群与蒙古包、近景草叶构成纵深；绿色使用橄榄绿、鼠尾草绿与深草绿，避免荧光绿和单一平色。
- 野马位于左侧、蒙古包位于右侧，中间保留大片草地；移动端重新定位主体，避免中央裁切后丢失。
- 场景为 `aria-hidden` 装饰，无交互与循环动画；明暗主题和 reduced-motion 均有独立适配。

### 4.3 Work 经历与项目

- 顶部使用 100vw 全幅纸版日照雪山：右上低饱和暖日、三层哑光山体、静态 SVG 油墨颗粒，底部渐隐进入暖纸底，不使用卡片外框或投影。
- 右侧雪坡设置两支沿登山绳有序上行的小队，人物带背包与登山杖，近大远小；移动端整组平移保留完整队列，不做循环爬升动画。
- 标题与说明沿用页面级排版，桌面从 160px 处开始，与经历正文左缘对齐。
- 融水始终位于左侧时间栏，桌面以 128px 时间轴为中轴，移动端对齐 22px gutter 内节点；离开山体后逐渐收束为 1px 时间线。
- 桌面左侧为 128px 年份时间线，右侧首行为公司 logo（左）与「部门 · 岗位」（右），下接奖项、摘要与项目入口。
- 默认全部收起，悬停自动展开且同一时间只展开一段，移出后保持最后一段；项目以静态纵向列表呈现，不使用卡片或第二层手风琴。
- 新增经历自动接入时间线；最后一段之后延伸 64px 并渐隐，不使用终点符号。
- 移动端场景高 250px、太阳 42px，山体简化裁切；年份移到公司上方，内容缩进 20px。

### 4.4 Notes 列表

- 页头：`Notes` + 一句说明（如「想到什么写什么，不定期更新。」），左侧对齐，宽 680。
- 按年份分组，年份用 Label 样式 + 右侧延伸的 1px 线。
- 每行：左侧日期 96px（等宽数字），右侧标题 + 一行摘要；行高约 92px，底部 1px 分隔线。
- 悬停：标题变强调色，箭头淡入；整行可点，但只让标题成为可访问链接，避免嵌套交互。

### 4.5 笔记正文

- 顶部返回链接 `← Notes`（13px，muted）。
- H1 48px，衬线；下方元信息「2026年10月18日 · 4 分钟」。
- 正文列 680px；H2 前留 56px、后 16px；段落 1.1em 间距。
- 引用块：左侧 2px 强调色线 + 斜体 + muted 色，不加背景。
- 代码块：深色墨块，圆角 14px，内边距 20px，右上角可选复制按钮（M3）。
- 图片：满宽，圆角 14px，`<figcaption>` 居中 13px muted。
- 文末：一条细线 + 「写于 2026 年 10 月」+ 返回列表链接；不做相关推荐。

### 4.6 响应式断点

| 断点 | 变化 |
| --- | --- |
| `< 761px` | 单列；H1 41px；导航保持完整宽度；经历改上下结构；日期移到标题上方 |
| `761–959px` | 容器 100% - 64px；项目仍两列、gap 16px；正文满宽 |
| `≥ 960px` | 容器 1160px；正文 680px；项目两列；导航与内容同宽、两端对齐悬浮 |
| `≥ 1280px` | 仅增加外边距，内容宽度不变（避免行长失控） |

> 断点从 PRD 的 640px 调整为 761px：在 640–760px 区间两列项目卡内文会挤成 2–3 行，单列又显得空；761px 同时覆盖主流竖屏平板。视觉稿已按此验证。

### 4.6 边界状态

| 场景 | 处理 |
| --- | --- |
| 还没有笔记 | 列表页显示一句「第一篇还在路上。」+ 邮箱订阅入口（mailto） |
| 项目没有外链 | 不显示箭头，卡片不可点，仍保留 hover 抬升 |
| 标题过长 | 正文页允许换行至 3 行，不截断；列表页最多 2 行 |
| 摘要缺失 | 构建失败（schema 必填），而不是运行时留白 |
| 404 | 同版式：大号 `404`、一句「这一页不存在，可能是链接过期了。」+ 回首页 |
| 图片加载失败 | 保留 alt 文案与占位底色，不出现破图图标 |

## 5. 内容模型

### 5.1 站点配置 `src/data/site.ts`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | Jacky Li |
| `tagline` | string | 是 | 一句话定位（H1 之外的补充） |
| `headline` | string[] | 是 | 首页大标题分行，支持一段斜体强调 |
| `intro` | string | 是 | 2–4 句简介 |
| `email` | string | 是 | 联系方式 |
| `socials` | `{label, href, icon}[]` | 是 | GitHub / X / 即刻等，2–4 个 |
| `siteUrl` | string | 是 | 用于 canonical、RSS、OG |

### 5.2 工作经历 `src/data/experience.ts`

`start`（YYYY）、`end`（YYYY 或 `present`）、`role`、`org`、`summary`（≤ 60 字）为必填；可选字段：`department`（部门，与岗位同行展示）、`logo` / `logoDark` / `logoHover`（官方品牌三态素材，常规 / 悬停 / 深色背景）、`website`（logo 点击跳转的官网）、`awards`、`projects`（关联 `src/data/projects.ts` 的项目 id）。数组顺序即展示顺序（时间倒序），不写排序逻辑。

### 5.3 个人项目 `src/data/projects.ts`

`name`、`summary`（≤ 40 字）、`url?`、`tags?`（2–4 个）、`mark?`（字标，如 `L`）。首版只放 2 个（Look、Tick），预留到 4 个的布局。

### 5.4 笔记 `src/content/notes/*.md`

```yaml
---
title: 为什么我又开始写博客
date: 2026-10-18
summary: 一句话说明这篇在讲什么，40–100 字，会出现在列表和首页。
tags: [写作, 工具]        # 可选，首版仅展示不筛选
draft: false               # true 时生产构建排除
cover: ./cover.jpg         # 可选，出现在正文顶部
updated: 2026-10-20       # 可选
---
```

**Schema 规则**（Astro Content Collections + Zod）：

- `title` 1–60 字；`summary` 20–120 字；`date` 合法日期且不晚于今天；`slug` 由文件名生成，只用小写字母、数字、连字符。
- 构建时校验失败即中断，避免「上线了但首页缺摘要」。
- 文件名约定：`why-i-write.md`，不把日期写进文件名（日期变更时不用改文件）。

## 6. 维护方案（谁维护、怎么维护）

### 6.1 角色与职责

| 角色 | 职责 | 权限 |
| --- | --- | --- |
| 站长（Jacky） | 写作、更新简介/经历/项目、审阅依赖升级 | 仓库 write |
| 自动化（CI） | 构建、部署、schema 校验、链接检查、OG 生成 | 只读 + 部署令牌 |
| 可选协作者 | 投稿或校对，通过 PR 提交 | 仅 PR，需你合并 |

**维护原则**：所有内容都在 Git 里，站点本身无状态。任何一台电脑 clone 下来就能继续维护；平台换掉也不影响内容。

### 6.2 写作 SOP（目标 ≤ 10 分钟）

1. **新建**：`pnpm new "标题"` 生成带 frontmatter 的 md 文件（约 10 秒）。
2. **写**：本地 Markdown 编辑器写作，`pnpm dev` 实时预览（写作时间不计入 10 分钟）。
3. **补元信息**：标题、日期、摘要三件套（约 1 分钟）。
4. **自检**：手机宽度预览一次；检查代码块、图片、链接（约 1 分钟）。
5. **发布**：`git add . && git commit -m "note: 标题" && git push`（约 30 秒）。
6. **确认**：CI 约 60–90 秒完成；打开线上页面确认（约 1 分钟）。

**没有本地环境时**：直接在 GitHub 网页端新建/编辑 md 文件并提交，同样触发部署。手机也能完成，代价是没有实时预览。

**写作门槛设定**：一篇 300–800 字即可发布，不追求长文。草稿放 `src/content/notes/_drafts/`（被 collection 排除），避免「没写完就不发」造成的空档。

### 6.3 维护日历

| 周期 | 事项 | 耗时 |
| --- | --- | --- |
| 每篇 | 写作 SOP + 构建通过 | 10 分钟 |
| 每周（可选） | 清草稿池、扫一遍错字 | 15 分钟 |
| 每月 | 合并依赖升级 PR、看一次访问统计（若启用）、检查外链 | 20 分钟 |
| 每季度 | 校对首页简介、经历、项目状态；确认「现在」的时间范围 | 30 分钟 |
| 每年 | 域名续费、导出备份、视觉小改版评估 | 1–2 小时 |

### 6.4 防停更机制

个人站点最常见的失败不是技术，是「三个月后不想写了」。对应设计：

- **降低单篇成本**：允许短笔记（一段话 + 一张图也算），不设「必须成文」的心理门槛。
- **首页只展示最近 3–5 篇**，不做「全部文章数量」的炫耀式统计，减少更新压力。
- **不承诺固定频率**：文案写「不定期更新」，避免自我违约。
- **草稿池**：灵感随手记，发布时再整理，减少「打开编辑器面对空白页」的阻力。
- **年度回顾**：每年把零散笔记整理成一篇「这一年」，既是一次复盘，也是一篇高质量内容。

### 6.5 备份、域名与迁移

| 项 | 方案 |
| --- | --- |
| 内容备份 | Git 仓库即备份；每年打一次 tag 并导出 zip 到本地/云盘 |
| 域名 | 你自己持有注册商账号，DNS 托管在 Cloudflare；不用他人代持 |
| 托管 | Cloudflare Pages 项目绑定你的 GitHub 账号 |
| 迁移 | 产物是纯静态 `dist/`，可迁到 Vercel、Netlify、对象存储 + CDN，无需改内容 |

## 7. 技术方案

### 7.1 选型

| 方案 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **Astro 5 + Tailwind 4** | 内容站一等公民、默认零 JS、MD/MDX 开箱即用、图片优化内置 | 需要懂一点 Astro 语法 | **推荐** |
| Next.js 静态导出 | React 生态熟悉 | 为静态内容引入较多运行时概念，JS 体积更大 | 备选 |
| Hugo / Hexo | 构建极快、主题多 | 模板语言老旧，定制视觉成本高 | 不推荐 |
| Notion / Framer 托管 | 零代码 | 绑定平台、样式受限、长期成本 | 不符合目标 |

**样式策略**：Tailwind 4 的 `@theme` 承载设计 token（颜色、字号、圆角、阴影），复杂排版（`.prose`、动效、毛玻璃）写在 `global.css` 的语义类里。避免整页 utility 堆叠导致改版困难。

### 7.2 架构

```
Markdown / TS 数据
      │
      ▼
Astro 构建（Node 22）
  ├─ Content Collections + Zod 校验
  ├─ Shiki 代码高亮（构建时）
  ├─ Astro <Image> 生成 WebP/AVIF
  └─ 静态 HTML + 少量内联 CSS
      │
      ▼
dist/ ──► Cloudflare Pages CDN ──► 访客
```

无服务端、无数据库、无运行时 API。唯一的客户端 JS 是主题切换（约 1KB）和可选的进场观察器（约 1KB）。

### 7.4 关键配置

- `output: 'static'`；`site` 从环境变量 `SITE_URL` 读取，保证预览环境 canonical 正确。
- 字体自托管在 `public/fonts/`：`instrument-serif-latin-400.woff2`（约 25KB）、`dm-sans-latin-var.woff2`（约 35KB），`font-display: swap`，仅预加载标题字体。
- 图片：正文图片放 `src/assets/` 走 `<Image>` 自动转 WebP/AVIF；上限宽 1600px，单张 ≤ 300KB。
- Shiki 双主题：亮色 `github-light`、暗色 `vesper`，通过 CSS 变量切换，不重复渲染。
- 内联首屏关键 CSS（约 4KB），其余样式异步加载；不做整站 CSS-in-JS。

### 7.5 性能预算

| 指标 | 预算 |
| --- | --- |
| LCP（4G 模拟） | < 1.3s |
| CLS | < 0.02 |
| INP | < 100ms |
| 首屏 JS | < 20KB（gzip） |
| CSS | < 25KB |
| 字体 | < 120KB（两个 woff2） |
| Lighthouse | 性能 ≥ 95，可访问性 100 |

### 7.6 SEO 与分享

- `title` 模板：`%s · Jacky Li`；首页用完整定位句。
- 每页独立 `description`、canonical、`og:title/description/image`、`twitter:card`。
- 结构化数据：首页 `Person`（name、url、sameAs 社交链接）；笔记页 `BlogPosting`（headline、datePublished、author）。
- `@astrojs/sitemap` + `@astrojs/rss`；`robots.txt` 指向 sitemap。
- OG 图：首版用一张统一品牌图；M3 用 Satori 按标题自动生成（每篇分享卡片不同）。
- `lang="zh-CN"`；日期用 `<time datetime>`。

### 7.7 部署流水线

```
feature 分支 ──PR──► 预览环境（唯一 URL，自动评论到 PR）
                         │
main 分支 push ──► 生产构建（astro check + build）──► Cloudflare Pages
                         │
                    失败则保留上一版本，控制台可一键回滚
```

- Node 22，包管理 pnpm；`pnpm build` 产物 `dist/`。
- 构建时跑 `astro check`（类型）+ schema 校验；任一失败阻断发布。
- 缓存：`/_astro/*` 一年 immutable；HTML 短缓存 + 自动失效。
- 每周一次链接检查（lychee），失效外链开 issue 提醒，不阻断部署。

### 7.8 统计与隐私

首版不装统计。需要时选 **Umami**（无 Cookie、不采集个人数据、脚本约 2KB），只记录 PV、来源、热门文章；不接 Google Analytics，避免 Cookie 横幅和额外体积。

### 7.9 可访问性

- 语义标签：`header/nav/main/article/footer`，标题层级不跳级。
- 键盘可达：焦点环 `2px solid var(--accent-ink)` + 2px offset；跳过导航链接（skip link）。
- 触控目标 ≥ 44×44px（导航项、主题切换）。
- 图标按钮带 `aria-label`；装饰性图形 `aria-hidden`。
- 暗色模式与浅色模式均通过对比度检查；`prefers-reduced-motion` 降级。
