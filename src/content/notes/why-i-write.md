上一次认真写博客是五年前。那时我用一个很复杂的静态站点生成器，配置了标签、搜索、评论和访问统计，花了一个周末才让首页看起来「像那么回事」。然后我写了三篇，就再也没打开过。

## 写得少，是因为门槛太高

每次想写点什么，先要决定放在哪个分类，要不要配图，标题够不够好，值不值得发出去。这些决定加在一起，比写作本身更累。后来我意识到，问题不在时间，而在我给自己设的默认标准：每篇都得是「作品」。

> 写作最难的部分从来不是写，而是允许自己写得不够好。

这次的做法反过来：先让它丑，先让它短，先发出去。一篇三百字的笔记，只要说清楚一件事，就比躺在草稿箱里的宏大提纲有价值。

## 这次改了什么

- 站点只保留三个页面：首页、列表、正文。没有分类，没有标签页。
- 每篇必须有标题、日期和一句摘要，其余都可以缺。
- 发布不需要登录后台，一次 `git push` 就够。
- 首页只展示最近三篇，不显示总篇数，减少「更新焦虑」。

于是整个发布路径变成这样：

```bash
# 新建一篇带 frontmatter 的草稿
pnpm new "为什么我又开始写博客" why-i-write

# 本地预览，确认排版
pnpm dev

# 发布
git commit -am "note: 为什么我又开始写博客" && git push
```

## 接下来

我不确定能写多久。可能一个月三篇，也可能三个月一篇。但至少这一次，工具不会再成为不写的理由。如果你也在犹豫要不要重新开始写，我的建议是：把标准降到「能发出去」，剩下的交给时间。
